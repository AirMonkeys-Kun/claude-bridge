## 一、今天做了什么

### 1. TCP Bridge 全流程实现（Phase 1 → 2 → 3）

通信桥从纯文件（queue.txt）迁移到 TCP + Named Pipe 直接分发：

**Phase 1 — bridge_agent.py（Windows TCP 服务端）**
- 监听 TCP :19850，接收沙箱命令
- 初版写入 queue.txt 复用 watcher 处理
- 文件：`D:\zebbingo\tools\claude-bridge\bridge_agent.py`

**Phase 2 — bridge_client.py（沙箱 TCP 客户端）**
- 从沙箱连接 172.16.10.254:19850
- TCP 失败时自动 fallback 到 queue.txt
- 文件：`D:\zebbingo\tools\claude-bridge\bridge_client.py`

**Phase 3 — Named Pipe 直接分发**
- bridge_agent 通过 `win32pipe.CallNamedPipe` 直接发给 worker，跳过 queue.txt + FileSystemWatcher
- Round-robin 遍历所有同类型 worker，3 次重试
- queue.txt fallback 带 `queue_serial` 锁保证并发安全

### 3. 部署过程中修复的 Bug

1. **UTF-8 BOM**：`.worker_pool.json` 由 PowerShell `Out-File` 写入带 BOM，`json.load()` 报错。修复：`encoding="utf-8-sig"`
2. **os.kill(pid, 0) 在 Windows 无效**：signal 0 是 Unix 特性。修复：用 `ctypes.windll.kernel32.OpenProcess` + `GetExitCodeProcess`，声明 `restype=c_void_p` 和 `argtypes` 支持 64 位 HANDLE
3. **并发 queue.txt 覆盖**：多线程同时写 queue.txt 互相覆盖。修复：`queue_serial` 锁保护 write + wait 整个周期
4. **单 worker 瓶颈**：`find_worker()` 只返回第一个 alive worker，10 并发全挤一个。修复：`find_all_workers()` 返回所有候选，round-robin 尝试

## 四、已知待办 / 可优化项

### 高优先级

1. **Guardian 集成 bridge_agent**：当前 Guardian 只监控 watcher，不监控 bridge_agent。如果 bridge_agent 崩溃，需要 Guardian 也自动重启它
   - 文件：`D:\zebbingo\tools\claude-bridge\guardian.ps1`
   - 改动：在 Guardian 的监控列表里加 bridge_agent.py 进程检测

2. **worker_factory 自动注册 bridge_agent 依赖**：worker pool 更新后 bridge_agent 缓存 30s TTL，如果 workers 全部重启，中间可能有空窗

### 中优先级

3. **bridge_client 在沙箱的部署路径**：当前 `bridge_client.py` 在 `D:\zebbingo\tools\claude-bridge\` 下，沙箱通过 virtiofs 访问。可考虑复制到沙箱 outputs 目录加速访问

4. **CallNamedPipe timeout 精确调优**：当前 timeout=0（立即返回），对偶尔慢的 worker 可能误判为 busy。可考虑设为 100-200ms

5. **并发测试中的 queue 延迟**：10 并发时有 1 个走 queue fallback（~800ms），可通过增加 generic worker 数量（当前 3 个）到 5-6 个来减少 queue fallback

### 低优先级 / Phase 4

6. **bridge_agent 替代 watcher 成为主入口**（TCP-MIGRATION-PLAN Phase 4）
7. **asyncio 替代 threading**（更轻量）
8. **WebSocket 双向通信**（支持推送通知）

## 六、Windows 平台踩坑速查（给下一个对话）

| 问题 | 症状 | 解决 |
|------|------|------|
| PowerShell JSON 有 BOM | `json.load()` 报 `Unexpected UTF-8 BOM` | 用 `encoding="utf-8-sig"` |
| `os.kill(pid, 0)` 不可用 | `OSError [WinError 87]` 或 `SystemError` | 用 ctypes `OpenProcess` + `GetExitCodeProcess` |
| ctypes handle 截断 | 64 位 HANDLE 被 trunc 为 32 位 | 必须设 `restype = ctypes.c_void_p` |
| CallNamedPipe 阻塞 | pipe busy 时等待整个 timeout | timeout=0 立即返回 |
| ScheduledTask RestartInterval | `PT10S` 报超出范围 | 最小 1 分钟 `PT1M` |
| queue.txt 并发覆盖 | 多命令同时写，前一个丢失 | `queue_serial` 锁保护 write+wait 原子性 |
